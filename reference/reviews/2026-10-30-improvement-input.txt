IN-BAPS의 현재 소스를 검토하고, 아래 개선 방향을 바탕으로 구현 계획을 수립해줘.

이번 요청은 우선 소스 재확인과 구현 계획 작성까지다. 코드 수정·DB 변경·배포는 하지 말고, 개선 항목별 현행 상태·변경 범위·우선순위·검증 방법을 정리해줘.

[프로젝트와 목적]

- 프로젝트: D:\work\in-baps
- 로컬 실행 주소: http://127.0.0.1:9000/
- IN-BAPS는 Open API 또는 업로드 파일의 데이터를 통계분석하고 시각화하여 의사결정을 지원하는 솔루션이다.
- 프로젝트 AGENTS.md를 먼저 읽고 준수한다.
- Git에 수정·미추적 파일이 많으므로 현재 작업 트리 전체를 기준으로 확인하고 기존 변경을 덮어쓰지 않는다.
- 이전 검토는 로그인 화면과 소스 기준이다. 로그인 이후 UI 동작을 실제 확인한 것으로 간주하지 않는다.

[현재 구현된 기능]

다음 기능을 없는 기능으로 판단하거나 중복 구현하지 않는다.

- 기본 분석 4종과 고급 통계 16종, 총 20종
- 고급 결과의 해석·가정·경고·유효/제외 표본·효과크기·신뢰구간·실행 파라미터·엔진 정보
- 분석 실행 결과 저장, 이력 조회, CSV/JSON 출력
- 차트 14종, PNG 출력, 설정 저장·복원
- 차트에 표시된 항목의 실제 원본 행 드릴다운과 그리드 검색·CSV
- 공통 데이터 카탈로그
- Open API JSON/XML, 필드 매핑, 페이지/offset 반복, 테스트·수집, TARGET 누적 적재
- 수집 배치 설정·실행 이력
- /dashboards GET/POST와 차트 묶음 저장 모델
  단, 대시보드 편집·공통 필터·활용 UI는 별도 확인이 필요하다.

[개선의 핵심 방향]

분석·차트 종류 확대보다 다음 흐름을 완성하는 데 우선순위를 둔다.

데이터 이해·준비 → 적합한 분석 선택 → 결과 이해 → 판단 근거 보관·활용

C/R/V는 독립적으로 진입하고 사용할 수 있게 유지한다.
이 흐름을 필수 직렬 파이프라인이나 자동 일괄 분석으로 구현하지 않는다.

[1. 메뉴 구성]

- C/R/V 브랜드는 유지하면서 업무명이 먼저 읽히도록 표시한다.
  예: 데이터 수집 · C-BAP / 통계 분석 · R-BAP / 시각화 · V-BAP
- 인법스 개요는 최근 데이터·최근 작업·이어서 할 작업·품질/수집 경고 중심으로 개선한다.
- 데이터 카탈로그 상세에 개요 / 컬럼·품질 / 데이터 준비 / 활용 이력을 제공한다.
- 저장한 인사이트는 통계 결과·차트·해석 메모·보고서를 찾는 통합 보관함으로 확장한다.
- DB 연결 설정과 SQL 작업실은 유지하고, 초보자에게는 필요한 시점에 연결 설정을 안내한다.
- 최상위 메뉴를 과도하게 늘리지 않는다.
- 메뉴 코드와 HTML·JS 연결 규칙, 관리자 접근 경계를 유지한다.

[2. 화면 전개]

① 개요의 KPI 정의
- 현재 M00001.js는 date/region/revenue/channel을 우선 사용하고, 없으면 첫 숫자 컬럼을 합산 지표로 사용할 수 있다.
- 지표·단위·집계·시간 컬럼·비교 기준을 사용자가 정의한 뒤 KPI로 표시한다.
- 정의 전에는 데이터 상태와 작업 현황을 보여 주는 방향을 검토한다.

② 업로드 미리보기
- 파일 선택 → 미리보기 → 자료형·날짜·결측·오류 확인 → 저장·사용 순서로 개선한다.
- 실제 적재 전에 대상·행 수·컬럼·변환 내용을 확인할 수 있게 한다.

③ R/V 직접 업로드
- 현재 공통 업로드 UI는 TARGET 연결과 테이블 생성 권한을 요구한다.
- 백엔드는 R/V 입력을 TARGET 연결 없이 SYSTEM에 보관하는 경로가 있다.
- ‘파일로 바로 분석·시각화’와 ‘TARGET에 적재해 사용’을 구분하는 방안을 검토한다.
- C-BAP의 TARGET 적재 원칙과 회원별 소유권·업로드 제한은 유지한다.

④ 모듈 간 맥락 전달
- 카탈로그·SQL에서 분석/시각화로 이동할 때 선택 데이터와 유효한 필터를 이어받는다.
- 카탈로그→V 이동 시 데이터 선택을 다시 요구할 가능성이 소스에서 발견됐다. 실제 UI로 재현·확인한다.
- 세션 변경과 데이터 변경 시 잘못된 선택·설정을 정리한다.

⑤ 질문 기반 분석 안내
- 기존 방법 검색·분류와 개별 실행을 유지한다.
- 분포 파악 / 집단 차이 / 변수 관계 / 영향 설명 / 유사 집단 등의 질문으로 적합한 분석을 좁혀 준다.
- 변수 유형·독립/대응 표본 구조·필요 조건과 추천 이유를 설명한다.
- 질문 선택만으로 분석을 자동 실행하지 않는다.

⑥ 저장 결과 탐색
- 저장 인사이트에 검색·태그·데이터셋 필터·페이지를 제공한다.
- 전체 카드의 데이터를 한꺼번에 조회하지 않고 필요한 미리보기부터 불러온다.
- V-BAP의 차트 유형·상세 설정·그래프 3열 구조는 유지한다.

[3. 업무 기능]

우선순위가 높은 순서로 검토한다.

A. 지표와 데이터 범위의 정확성
- 원천·조회시각·필터·단위·집계·전체/조회/유효/제외 행 수·잘림 여부를 공통 표시한다.
- 카탈로그의 ‘전체 CSV 내보내기’는 실제 limit=20000 요청과 명칭·범위를 일치시킨다.
- 기존의 올바른 표본 제한·경고 표시를 유지한다.

B. 데이터 준비·품질
- 자료형 변경, 날짜·단위 정규화, 결측 처리, 중복 검사, 범주 통합, 역문항 재코딩
- 원본 보존, 적용 전후 비교, 파생 데이터셋과 변환 이력
- 계산 기능은 허용된 선언형 연산으로 제한하고 임의 코드·수식 실행을 허용하지 않는다.
- 기존 프로파일 결과를 수정·정제 작업으로 연결한다.

C. 데이터 결합
- API와 업로드 파일의 키 기반 조인, 여러 파일의 유니온
- 중복 키·미결합 행·결합 후 행 수 증가·자료형 불일치를 미리 확인한다.

D. API 중복·증분 정책
- 기존 배치 기능을 활용한다.
- 실행별 이력 누적 / 업무키 기준 최신값 / 변경분 수집을 구분한다.
- 신규·중복·갱신 건수, 마지막 성공 시점, 스키마 변화를 표시한다.
- SYSTEM/TARGET 커밋 불명확 시 자동 재시도 금지와 잠금 보호를 유지한다.

E. 결과의 기준시점·재현성
- 통계 이력은 실행 당시 결과이고 저장 차트는 열 때 최신 데이터를 조회한다.
- ‘실행 당시 결과’와 ‘최신 데이터로 조회’를 명확히 구분한다.
- 추출 조건·데이터 지문·변환 버전을 기록하는 방안을 검토한다.
- 필요 시 사용자가 명시적으로 선택하는 스냅샷을 제공한다.
- 기존 설정으로 개별 재실행하고 이전 결과와 비교할 수 있게 한다.

F. 분석별 결과 시각화
- 회귀: 계수와 신뢰구간, 관측값 대 적합값, 잔차
- PCA: 설명분산, 점수 산점도
- 군집: 군집별 분포·중심·프로파일
- 현재 공통 name/value 막대 표현을 실제 산출물에 맞게 개선한다.
- 기존 해석·가정·진단을 새 기능처럼 중복 구현하지 않는다.

G. 대시보드와 의사결정 산출물
- 기존 대시보드 API 골격을 활용한다.
- 저장 차트·KPI·메모를 묶는 편집 화면
- 공통 기간·범주 필터, 선택 조건 표시·초기화, 차트 간 탐색
- 업무 질문·핵심 발견·근거·한계·권고 조치·담당자·검토일을 보관하는 의사결정 노트
- 출처·조회 범위·통계 결과·차트·해석을 묶는 PDF/PPT 보고서

H. 후속 확장
- Excel 파일의 시트 선택·헤더·날짜 미리보기
- 일/주/월 집계, 전기 대비·증감률·누계
- 팀별 보기/편집 권한과 검토 코멘트
- 대용량은 한도 증대보다 DB 측 집계·명시적 표본·비동기 작업 중심으로 설계
- 현재 10MiB·20,000행·100컬럼과 서버 메모리 분석 범위를 정확히 고려한다.
