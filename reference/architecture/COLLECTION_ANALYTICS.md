# C-BAP Open API · R-BAP 고급 통계 · V-BAP 드릴다운

2026-10-29 구현 기준. 회원 세션·CSRF·데이터/연결 소유권·서버 모듈 활성 검증을 공통으로 적용한다.

## C-BAP 사용 순서

C-BAP 상단의 파일·직접 입력 / Open API 탭으로 방식을 선택한다. 아래 연결 데이터셋은 두 방식이 공유하며 수집유형을 구분한다. Open API 탭의 한국 GDP·인구·기대수명 예제는 실제 공공 응답 미리보기와 편집 가능한 설정을 제공한다.

1. DB 연결 설정에서 쓰기가 허용된 본인 TARGET을 등록하고 연결을 확인한다.
2. C-BAP → 새 API 등록에서 이름, 최종 HTTPS URL, GET/POST, TARGET을 지정한다. URL에는 쿼리 문자열을 붙이지 않는다.
3. INPUT 행에 Query/Header/Body 위치, 이름, 문자/숫자/참거짓/JSON 자료형, 값을 입력한다. POST 본문은 JSON 객체 또는 Form URL encoded를 지원한다. 중첩 본문은 해당 파라미터를 JSON 자료형으로 설정한다.
4. API 키·토큰은 비밀값으로 지정한다. 인증 관련 이름도 서버가 비밀값으로 처리한다. 저장된 값은 다시 표시하지 않으며 수정 시 빈칸은 기존 값을 재사용한다. 다른 회원의 소스 ID로 재사용할 수 없다.
5. JSON 레코드 경로는 `data.items`, `$[1]`, XML은 `response/body/items/item`처럼 지정한다. OUTPUT은 컬럼명, 필드 경로, 자료형, 필수 여부를 지정한다. JSON 경로는 점·배열 인덱스, XML은 요소 경로·`@속성`을 지원한다. XPath 함수·와일드카드·임의 코드 실행은 지원하지 않는다.
6. API 연결 테스트에서 첫 페이지의 최대 20개 변환 행을 확인하고 TARGET 연결 테스트를 실행한다. 테스트는 TARGET 테이블·행을 만들지 않는다.
7. 설정을 저장한 뒤 TARGET 수집 실행을 누른다. 실행은 저장된 설정을 사용하며 전용 테이블에 추가 적재한다. 파일 수집·직접 JSON 입력도 계속 사용할 수 있다.
8. 배치를 등록하면 5분~7일 간격과 다음 실행 대상 시각을 SYSTEM에 보관한다. Cron이 실행되어야 예약 작업을 처리한다. 웹 화면이 열린 상태에 의존하지 않는다.

예를 들어 World Bank의 `/v2/country/KOR/indicator/NY.GDP.MKTP.CD` 응답은 `format=json`, `per_page=5`를 Query 입력으로 보내고 레코드 경로 `$[1]`을 지정한다. OUTPUT은 `year ← date (문자)`, `value ← value (숫자)`로 매핑할 수 있다. 예시는 자동 등록하거나 자동 수집하지 않는다. 실제 API 조건·이용 정책은 공급자의 문서를 따른다.

### 적재·중복·제한

- API별 전용 TARGET 테이블에 추가한다. 기존 고객 테이블을 덮어쓰거나 자동 MERGE하지 않는다. 같은 원천을 다시 수집하면 새 실행으로 누적되며 원천 업무 키 기준 중복 제거는 하지 않는다.
- PK는 `BAPS_RUN_ID, BAPS_ROW_ID`다. `BAPS_COLLECTED_AT`과 `BAPS_RAW_DOCUMENT` CLOB에 수집 시각·레코드별 JSON/XML을 저장한다. 입력 인증값이 반사된 내용은 마스킹하므로 원문은 바이트 단위 원본 보증이 아닌 레코드 구조 보관이다.
- 매핑 컬럼은 안정적인 물리명 `C001...`을 사용하고 카탈로그 SQL 별칭에 사용자 컬럼명을 보존한다. 매핑 `json`은 CLOB, 숫자/참거짓은 NUMBER, 문자는 VARCHAR2(4000 BYTE)다. 큰 식별자·고정 소수 정밀도가 필요한 값은 문자로 매핑한다. 부동소수 변환으로 정밀도를 잃는 숫자 입력은 거부한다.
- 첫 테이블 준비 이후 TARGET 연결·OUTPUT·응답 형식 변경은 새 소스로 등록한다. 테이블 소유 표식·실제 컬럼 구조를 확인하고 다르면 적재를 차단한다. 소스 삭제는 설정·배치·이력을 삭제하며 TARGET 데이터와 카탈로그는 보존한다.
- 공개 HTTPS 443만 지원한다. DNS 결과가 사설·루프백·링크 로컬·특수 주소를 포함하면 거부하고 검증한 IP로 접속하되 원래 호스트의 TLS 인증서를 확인한다. 리디렉션·프록시·쿠키·압축 응답을 지원하지 않는다. XML 외부 엔티티·DTD를 차단한다.
- 한 실행 최대 10MiB 응답, 20페이지, 20,000행, 100컬럼, 페이지당 요청 크기 최대 2,000을 제한한다. 제한 도달 여부를 결과에 보관한다. 페이지/Offset Query 파라미터 방식만 지원하며 OAuth 자동 갱신·커서/다음 링크 방식은 별도 개발 범위다.
- 같은 소스의 수동·배치 실행은 SYSTEM 행 잠금으로 직렬화한다. TARGET 커밋과 SYSTEM 기록은 분산 원자 트랜잭션이 아니므로 불명확한 결과는 `UNKNOWN`으로 잠금을 유지한다. 5분 보호 기간 이후 실행 ID로 실제 TARGET 상태를 확인하고 명시적으로 해제한다. 이미 저장된 데이터를 되돌리거나 안전한 자동 재수집을 보증하지 않는다.

## Render 운영

`render.yaml`은 Python Web Service와 `in-baps-collection` Cron을 정의한다. 웹 Build/Start 명령은 기존 명령을 유지한다. Cron도 같은 빌드 스크립트로 설치하고 `python -m backend.collection_worker --once`를 `*/5 * * * *`에 실행한다. 기본 한 번에 20개 예정 작업, `--limit 1..50`을 지원한다. 작업이 오래 걸리거나 대기 작업이 많으면 실제 시작이 늦어질 수 있다.

Cron은 웹 서비스의 SYSTEM DB 계정·비밀번호·DSN·Wallet 비밀번호·`BAPS_SECRET_KEY`를 Blueprint 참조로 공유한다. **Wallet Secret Files는 Cron 서비스에도 별도로 등록해야 한다.** `tnsnames.ora`, `ewallet.pem`, `DB_WALLET_PATH=/etc/secrets`를 준비하고 같은 TARGET 서버 프로필을 사용할 수 있어야 한다. 모듈을 환경변수로 제한하면 웹과 Cron의 `BAPS_MODULES`도 일치시킨다. DB migration은 자동 시작 단계에서 실행하지 않으며 배포 전에 명시적으로 적용한다.

Render Cron은 UTC 일정과 별도 과금 정책을 사용하며 영구 디스크를 제공하지 않는다. 일정·실행 이력·수집 결과는 Oracle에 보관한다. 로컬 `.runtime/ddl/` 실행 SQL은 Render 재배포 후 보존되지 않을 수 있으므로 필요한 구조는 TARGET DBMS에서 내보내거나 별도로 백업한다. 실행 중 수동 Trigger Run은 진행 중 Cron을 중단시킬 수 있으므로 불명확한 실행 잠금의 상태를 확인한다. [Render Cron 공식 문서](https://render.com/docs/cronjobs), [Blueprint 공식 규격](https://render.com/docs/blueprint-spec).

## R-BAP 분석 범위

기본 4종은 프로파일·집계·Pearson 상관·텍스트 빈도다. 기본·고급 모두 검색 가능한 방법 목록에서 선택해 개별 실행한다. 기본 4종 일괄 실행은 사용자 요청으로 제거했다.

| 고급 방법 | 주요 결과 |
|---|---|
| 기술통계 | 유효/결측 N, 평균·분산·분위수·왜도·첨도, 평균 CI |
| 정규성 | Shapiro–Wilk, D’Agostino, 상수·표본 조건 표시 |
| 일표본 / 독립 / 대응 t | t·자유도·p, 차이 CI, 효과크기; 독립은 Welch |
| 일원 ANOVA | 집단 요약·ANOVA·효과크기·Levene·Tukey HSD |
| Mann–Whitney / Kruskal–Wallis / Wilcoxon | 순위 검정·효과크기, Kruskal 쌍별 Holm 보정 |
| 교차표 | 관측/기대 빈도·카이제곱·Cramér V, 2×2 Fisher |
| 상관 유의성 | Pearson/Spearman·쌍별 N·p·Holm, Pearson Fisher CI |
| 다중 선형회귀 | 계수·기본 HC3 표준오차·CI·VIF·잔차 진단, 별도 홀드아웃 |
| 이항 로지스틱 | 비정규화 Logit 계수·오즈비·CI·적합 지표, 별도 AUC·혼동행렬 |
| PCA | 표준화 선택·고유값·설명 비율·성분 가중치·관측 점수 |
| K-means | 표준화 선택·군집 크기/중심·관측 배정·Silhouette |
| 신뢰도 | Cronbach α·수정 문항-총점 상관·문항 제거 α |

분석은 조회된 최대 20,000행에 한정한다. 선택 수치 컬럼은 최대 20개, 신뢰수준은 90/95/99%다. 앞자리 0 식별자 등 기존 수치 판별 정책을 지키며, 분석별 결측 제거 정책·사용/제외 행 수를 보관한다. Shapiro는 최대 5,000행, Silhouette는 최대 2,000행 표본, PCA/군집의 관측별 출력은 앞 2,000행이며 각 제한을 결과에 표시한다. 화면 표는 앞 100행, 표 CSV는 저장된 표 전체를 내보낸다.

회귀계수 추론은 전체 유효 표본의 모형이다. 충분한 표본의 검증 지표는 별도로 나눈 훈련/검증 표본에서 계산하며 표준화는 훈련 표본에만 적합한다. 재현 시드는 1729다. 상수·선형 종속·분리·수렴 실패를 검사한다. 범주형 설명변수 자동 더미화, 복합 표본 설계, 생존/시계열/혼합 모형, SAS/R/SPSS 코드 실행은 현재 지원하지 않는다. 통계 패키지의 모든 절차를 대체한다고 표시하지 않는다.

실행 파라미터·엔진 버전·표본 정보와 결과 표를 기존 소유 카탈로그에 저장한다. 목록은 요약만 조회하고 선택한 이력의 원래 결과를 다시 읽는다. 현재 설정 변경이 이미 표시된 결과의 분석명을 바꾸지 않는다. 표 CSV·전체 JSON·V-BAP 분석 결과 전달을 지원한다.

## V-BAP 원본 연결

기존 14종 차트의 실제 표시 항목을 원본 행 인덱스와 연결한다. 범주 집계, 히트맵 양축, 네트워크 연결/노드, 선버스트 부모/자식, 박스플롯 등 각 의미에 맞게 기여 행을 구한다. 중복 좌표 산점도는 개별 원본 행을 식별한다. 레이더 도형 클릭은 표시 지표 전체이며 개별 지표는 선택 목록으로 조회한다.

검색·정렬·25/50/100행 페이지·현재 필터 CSV·행 상세·차트 포함 여부와 포함 행만 보기·선택 경로/초기화를 제공한다. 키보드 항목 선택도 가능하다. 행 상세와 툴팁은 escape하고 CSV 수식 주입을 방어한다. 그리드의 원본은 현재 조회 데이터이며 서버 전체 원천을 무제한 조회하는 기능은 아니다.
