# 로그인 배치·화면 로딩 검증

검증일: 2026-10-29

## 변경

- 로그인 배경의 좌우 색상과 글자 크기를 유지하고, 콘텐츠를 화면 중앙 약 1080px 범위에 배치했다. 모바일에서는 기존 세로 배치를 유지한다.
- 로그인 성공 시 로그인 DOM을 즉시 제거한다. 초기 데이터 조회 후에만 메인 화면을 렌더링하므로 로그인 폼이 메인에 남지 않는다.
- `page-loading.js`는 별도 native modal dialog로 화면 정중앙에 로딩 막대를 표시한다. 배경을 흐리게 처리하고 클릭·Tab·Escape 및 검색 단축키로 배경을 조작하지 못하게 한다. 중첩 작업을 추적하고 모두 끝나면 해제한다.
- 초기 준비 실패는 차단을 해제하고 재시도 화면을 표시한다. 인증·권한 변경 이후 오래된 초기 응답이 화면을 다시 그리지 않도록 확인한다.
- 일반 업무 진행의 오른쪽 이동 레이어는 유지한다. 화면 준비 중에만 해당 레이어를 숨겨 중복 표시하지 않는다.

## 검증 결과

- JavaScript 구문 검사 통과.
- 전체 UI 13개 중 기존 업무·분석·시각화·모바일·레이어 검사 12개 통과. 추가한 로그인 지연 검사에서 Tab 초점이 dialog 밖 body로 이동함을 발견해 명시적인 초점 고정을 추가했다. 보정 후 해당 로그인 검사도 통과했다.
- 초기 조회를 지연하여 로그인 DOM 제거, 중앙 좌표, 배경 도움말 클릭 차단, Escape·Tab·검색 단축키 차단을 확인했다.
- 초기 데이터 조회 503 오류를 명시적으로 주입해 차단 해제와 재시도 성공을 확인했다. 회귀 검사는 격리 SQLite 서버에서 실행했다.
- 실제 9000 서비스에서 아이디 기본 초점, 정상 로그인, 초기 조회 지연 중 중앙 로딩창, 로그인 잔상 제거, 메인 준비 후 해제를 확인했다. DB 업무 데이터는 변경하지 않았다.
- 2560·1920·1366·900·390·320px 폭에서 로그인 화면의 가로 넘침이 없음을 확인했다. 캡처는 Git 제외 `.runtime/qa/login-centered-*.png`, `login-central-loading.png`에 보관한다.

원격 Git/Render 배포는 수행하지 않았다.

## 중앙 로딩 디자인 개선

- 흰색 스피너 카드에서 네이비·틸·코럴 기반 데이터 시각화 패널로 변경했다. 데이터 흐름, 중심 막대, 회전 궤도, 분석 파형과 얇은 이동 막대를 SVG/CSS로 표현한다.
- 장식 그래픽은 `aria-hidden`이며 실제 상태 문구는 기존 live status로 안내한다. 가짜 완료율이나 AI 분석 단계는 표시하지 않는다.
- 1440·390·320px에서 중앙 정렬과 패널 내부 가로 넘침을 확인하고 캡처를 검토했다. 동작 줄이기 시 애니메이션 정지, Escape 차단, Tab 초점 유지, 완료 시 해제를 확인했다.
- 디자인 변경 후 로그인 지연·배경 차단·초기 실패 복구 회귀 검사 통과. 확인 과정에서 DB 업무 데이터를 쓰지 않았다.
- 캡처: Git 제외 `.runtime/qa/loading-design-*.png`.

## 일반 화면 이동용 간소화

- 기본 중앙 로딩은 최대 340px의 작은 패널에 로고·실제 상태 문구·얇은 흐름 막대만 남겼다. 분석형 그래픽은 별도 `analysis` 옵션으로 보관하고 일반 업무의 오른쪽 진행 창은 그대로 유지했다.
- 1440·390·320px 화면 경계와 중앙 정렬, 기본 그래픽 숨김, 분석형 선택 및 중첩 작업 종료 후 기본형 복원을 확인했다.
- Escape·Tab 차단과 종료 후 해제, 로그인 지연·배경 차단·초기 실패 복구 회귀 검사를 통과했다. DB 업무 데이터 쓰기는 하지 않았다.
