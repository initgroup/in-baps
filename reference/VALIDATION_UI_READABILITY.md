# 화면 가독성·이동 레이어 검증

검증일: 2026-10-29

## 변경

- 전체 글자 크기를 rem 기준으로 확대하고 본문·보조 설명·표·차트 축의 대비를 강화했다. 배경·내비게이션·차트 색상 구성은 유지하고 흰색 버튼 글자가 읽히도록 주요 버튼의 코럴 명도를 낮췄다.
- 실제 값은 진한 글자, 입력 예시는 `예:`·기울임꼴·점선 테두리로 구분한다. 테이블 생성 창은 최대 860px, 일반 입력 높이는 46px이며 모바일 컬럼 행은 세로로 재배치한다.
- `layers.js`에서 폼/확인 다이얼로그와 알림을 관리한다. 드래그·방향키 이동, 화면 경계 유지, Escape 닫기, 오류 지속 표시, 일반 알림 시간 제한, 동작 줄이기를 적용했다.
- 알림은 열린 다이얼로그 안에 소속시킨 뒤 Popover API로 최상위 레이어에 표시한다. 입력 오류를 보면서 폼을 수정할 수 있고 입력값은 보존된다.
- 로그인·DB 연결 오류·입력 검증·DB 작업 알림을 공통 레이어로 연결했다. 작업 결과와 지속적인 상태 설명은 원래 화면에도 유지한다.

## 수행 결과

- `npm.cmd run check`: 통과.
- `npm.cmd run test:charts`: 4개 통과.
- 기존 UI 회귀 9개 통과: 회원/세션, 대시보드/모바일, R 분석, R→V, 14개 차트, C 수집 계약, TARGET SQL/DML/그리드/DDL 계약, R/V 단독 구성.
- 추가 UI 검증 2개 통과: 필수 입력 팝업/초점, 로그인 오류 지속 표시, 팝업 위 알림의 클릭·드래그, Escape로 알림만 먼저 닫기, 제목 방향키 이동, 1920×1080에서 390×844로 축소 시 화면 경계와 가로 잘림 방지.
- 모바일 컬럼 체크박스 배치 보정 후 해당 DDL 검증을 다시 통과했다.
- 실제 9000 서비스에서 공통 모달의 표시 및 방향키 이동 좌표를 별도로 확인했다.
- 데스크톱·모바일 캡처를 확인했다. 캡처는 Git 제외 `.runtime/qa/readability-ddl-*.png`와 `dashboard-*.png`에 있다.
- 관리자 비밀번호 Git 배포 제외 검사 통과.

UI 회귀는 격리 SQLite SYSTEM 및 명시적으로 모의한 TARGET API를 사용한다. 이번 화면 변경을 위해 실제 Oracle 테이블 생성이나 변경을 실행하지 않았다. 원격 Git/Render 배포는 수행하지 않았다.
