# 공통 진행 표시·알림 검증

검증일: 2026-10-29

## 구현 범위

- 공통 `api()`의 작업명·경과 시간·무정률 막대, 작업별 수명 관리, 실패 안내를 적용했다. 페이지 HTML 준비와 IN-SIGHT 차트 생성도 진행 창을 사용한다.
- 파일 업로드는 XMLHttpRequest 전송 바이트 이벤트로 진행률을 표시한다. 업로드 완료 후 서버 검증·DB 저장 대기 단계에서는 %를 제거한다. 기존 세션 쿠키·CSRF 헤더·JSON 응답 계약을 유지한다.
- CSV 내보내기는 500행씩 처리하고 완료 행 수로 %를 계산한다. 렌더링 기회를 제공하며 백그라운드 탭에서 프레임이 멈춰도 처리가 이어지도록 시간 기반 대기 상한을 둔다.
- 서버 DB 작업의 중간 건수·전체 건수를 제공하는 API는 아직 없다. SQL·분석·DB 적재에 임의의 %나 예상 완료 시간을 표시하지 않는다.
- 오른쪽 위 진행 창과 오른쪽 아래 알림은 공통 레이어 관리 기능을 사용한다. 입력 팝업이 열리거나 닫혀도 진행 창을 유지하며, 드래그·방향키 이동·화면 경계·동작 줄이기를 지원한다.
- 작업 완료·실패·요청 중단은 `finally`에서 정리한다. 로그인 세션 종료 시 이전 작업 표시를 제거한다. 진행 창을 닫는 것으로 DB 실행이 취소된다고 표현하지 않는다.

## 검증 결과

- 프론트 JavaScript 구문 검사 통과.
- 전체 Playwright 브라우저 회귀 13개 통과. 기존 회원·SQL UI·분석·14종 차트·독립 모듈 흐름을 포함한다.
- 동시에 두 요청을 시작하고 하나가 완료되어도 다른 작업은 표시되는 것을 확인했다. 나머지 요청의 HTTP 오류 뒤 진행 표시가 사라지고 오류 알림 하나가 남는 것을 확인했다.
- 입력 팝업 유지, 기존 필드 값 보존, 진행 창 키보드 이동과 너비 유지, 모바일 390×844 화면 경계를 확인했다.
- 5,000행 CSV 변환에서 실제 중간 진행률이 표시되고 완료 후 진행 창이 사라지는 것을 확인했다.
- 브라우저 전송 모의에서 50% 전송률·CSRF 전달·전송 완료 후 무정률 DB 처리·완료 정리를 확인했다. 실제 FormData 전송과 데이터셋 연결은 기존 TARGET API 계약 검사도 통과했다. 이 검사는 원격 Oracle 파일 적재를 새로 실행한 검증은 아니다.
- 실제 9000 서비스에서 기존 관리자 소유 Oracle 연결 테스트가 성공했다. 빠른 접속에서도 화면을 촬영할 수 있도록 테스트 브라우저에만 실제 응답 전달 지연 1.2초를 적용했다. 응답 내용은 변경하지 않았고 진행 창·단일 완료 알림·진행 상태 정리·브라우저 오류 없음을 확인했다. DDL/DML은 실행하지 않았다.
- 비공개 관리자 비밀번호 배포 파일 검사 통과. Git push·Render 공개 배포는 수행하지 않았다.

브라우저 검사 결과와 화면 캡처, 실제 서비스 확인 스크립트는 Git 제외 `.runtime/qa/`에서 관리한다.
