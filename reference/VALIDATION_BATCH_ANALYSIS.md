# R-BAP 일괄 분석 검증

검증일: 2026-10-29

## 구현

- 기존 단일 분석 옆에 모든 방법 일괄 분석을 제공한다. 그룹·수치·집계·텍스트·상관관계 컬럼을 설정한 뒤 4가지 분석을 순차 실행한다.
- `frontend/js/analysis-batch.js`에서 실행 상태와 결과 카드를 관리하고 `M02001.js`의 결과 표시·CSV·V-BAP 연결을 재사용한다. 기존 `/api/analysis`의 회원 소유권·활성 모듈 검증·SYSTEM DB 저장을 유지한다. 새 DB 오브젝트나 마이그레이션은 없다.
- 처리 방법 수에 근거한 공통 진행 창을 표시한다. 개별 실패 후 계속 진행하고, 인증/권한 오류·화면 이동 시 후속 요청을 중단한다. 이미 전달된 서버 요청은 완료될 수 있다.
- 좁은 화면에서 긴 결과 표가 본문 폭을 늘리지 않도록 분석 결과 영역의 최소 너비를 조정했다.

## 격리 UI 검사

기존 분석 회귀 검사에 일괄 경로를 추가했다. 별도 테스트 서버·SQLite를 사용했다.

- 4개 단일 분석과 4개 일괄 분석의 실제 API 결과 계산·기록 저장 확인.
- 방법별 결과 전환, 선택한 집계 결과의 CSV 및 V-BAP 데이터셋 연결 확인.
- 수치 컬럼이 없는 데이터는 건수 집계로 처리하고 상관관계만 건너뜀 확인.
- 집계 오류를 명시적으로 주입했을 때 나머지 3개 결과 저장 및 실패 사유 표시 확인.
- 첫 요청을 지연한 상태에서 중복 실행 버튼 잠금과 진행률 0% 확인. 화면 이동 후 첫 요청만 완료하고 나머지 3개는 미실행으로 표시함을 확인.
- 기존 4종 분석 결과의 V-BAP 필드 연결 회귀 통과.
- C-BAP·V-BAP이 비활성화된 R-BAP 단독 구성 회귀 통과. 관련 UI 검사 총 3개 통과.
- 프론트 JavaScript 구문 및 관리자 비밀번호 Git 배포 제외 검사 통과.

## 실제 서비스 확인

9000 서비스의 기존 소규모 데이터셋으로 일괄 분석을 실행했다. 4개 성공 응답의 ID가 실제 SYSTEM DB의 회원 분석 기록에서 조회됨을 확인했다. 원본 데이터셋·고객 테이블·TARGET 연결 설정은 변경하지 않았으며 분석 기록 4개만 추가했다.

이후 화면 검증에서는 저장된 결과를 읽어 브라우저 응답으로 재현하여 분석 기록을 추가하지 않았다. 1366px, 390px, 320px에서 설정 팝업·결과 카드·결과 전환과 가로 넘침을 확인했다. 기록 ID·캡처는 Git 제외 `.runtime/qa/batch-live-result.json`, `batch-config-*.png`, `batch-results-*.png`에 보관한다.

원격 Git/Render 배포는 수행하지 않았다.
