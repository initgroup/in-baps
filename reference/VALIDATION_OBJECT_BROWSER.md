# TARGET 오브젝트 탐색기 검증

검증일: 2026-10-29

## 빈 목록의 원인

실제 BASE03의 `USER_OBJECTS`를 읽기 전용으로 조회했을 때 총 26개(TABLE 8, INDEX 14, PROCEDURE 1, VIEW 1, LOB 2)가 있었다. 기존 공유 연결 목록은 로그인 회원이 해당 연결에서 생성·적재하여 등록한 테이블만 허용했다. 관리자 연결의 등록 테이블이 0개여서 목록도 0개였으며, `INIT$_` 전체를 일괄 제외하는 조건 때문은 아니었다.

## 변경

- `backend/object_browser.py`: 연결별 목록 정책, 역할별 표시 범위, 시스템/관련 오브젝트 식별, 목록 전용 항목 구분, 필터 적용 후 1,000개 표시 제한.
- 관리자 공유 연결의 기본 목록 범위는 현재 스키마 전체, 일반 회원은 소유 테이블과 관련 인덱스/트리거이다. 목록 표시 범위는 SQL·그리드·DDL 권한을 확대하지 않는다.
- GET/PUT `/api/connections/{id}/object-filter`: 소유권·CSRF 검증 후 기존 연결 JSON에 표시 정책을 저장한다. 행 잠금 후 병합하여 비밀번호·소유 테이블 목록을 보존한다. 추가 DDL은 없다.
- `database/SQL/target.sql`: `USER_OBJECTS`와 `USER_INDEXES`/`USER_TRIGGERS`의 연관 테이블 조회를 파일로 관리한다. 검색은 바인딩하고 `_`, `%`, 백슬래시를 일반 검색 문자로 이스케이프한다.
- M90002와 M90003에서 같은 목록 설정 팝업을 사용한다. 접두어·유형 제외와 시스템 숨김을 설정할 수 있으며 서버 공유 연결의 접속 정보는 수정하지 않는다.
- 테이블·뷰·구체화 뷰·함수·프로시저·패키지·인덱스·트리거·시퀀스 9종 폴더와 건수를 제공한다. LOB 내부 오브젝트는 지원 유형에 포함하지 않는다. 긴 이름은 줄바꿈으로 표시한다.

## 확인 결과

- Python 전체 검사 **60개 통과**: 기존 회원·TARGET·JSON·migration 검사와 목록 정책 검사 5개를 포함한다. 격리 SQLite·모의 Oracle 커서를 사용한 자동 검사이다.
- 브라우저 회귀 13개 경로를 확인했다. 최초 실행에서 12개 통과 후, 닫힌 팝업의 DOM이 유지되는 기존 동작에 맞춰 검사 조건을 수정했고 해당 DBMS 경로를 재실행해 통과했다.
- 유형 폴더 열기, 함수 소스 화면, 접두어 `TMP_`와 `TMPX` 구분, 인덱스 제외, 시스템 항목의 목록 전용 동작, DB 설정 화면에서 저장값 재확인, 기본값 복원, 모바일 폭을 검증했다.
- 실제 9000 서비스의 BASE03 기본 목록 **6개**, 시스템 관련 제외 **18개**를 확인했다. 숨김 해제 시 지원 유형 **24개**를 확인했다. 이는 접두어만 세는 결과가 아니라 시스템 테이블에 속한 인덱스까지 포함한 판별 결과이다.
- 실제 Oracle SYSTEM 저장소에 필터를 저장하고 재조회하여 적용을 확인한 후 기존 표시 설정으로 복원했다. 연결 암호나 TARGET 업무 데이터·오브젝트는 변경하지 않았다.
- 시스템 숨김을 해제한 상태에서도 보호 회원 테이블의 SELECT와 DDL 요청이 각각 403으로 차단되는 것을 확인했다.
- 실제 관리자 브라우저에서 유형 폴더, 목록 전용 항목 선택, PC·모바일 목록 설정 창을 확인했다. 브라우저 JavaScript 오류는 없었다.
- JavaScript 구문 검사와 비공개 관리자 비밀번호 배포 파일 검사 통과. Git push·Render 공개 배포는 수행하지 않았다.

실제 DB 확인 결과와 화면 캡처는 Git 제외 `.runtime/qa/`에 보관한다. 기본 목록에 표시된 기존 QA 수집/테이블은 이전 테스트 회원 소유의 실제 오브젝트이며 이번 개편에서 생성한 샘플이 아니다.
