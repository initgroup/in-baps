# 인법스 · IN-BAPS

정식 명칭: **INIT-Bigdata Analysis Platform System**

| 모듈 | 정식 명칭 | 화면 제목 / 메뉴 보조명 |
| --- | --- | --- |
| C-BAP | Collection - Bigdata Analysis Platform | C-BAP 데이터 수집 / 데이터 수집 |
| R-BAP | Research - Bigdata Analysis Platform | R-BAP 데이터 분석 / 데이터 분석 |
| V-BAP | Visualization - Bigdata Analysis Platform | V-BAP 시각화 / 데이터 뷰어 |

각 모듈 화면의 제목 바로 아래에 정식 명칭을 표시합니다. `IN-SIGHT`는 차트·시각화 경험명으로 유지합니다.

IN-BAPS는 C-BAP 수집, R-BAP 분석, V-BAP 시각화를 연결하는 **회원 전용 의사결정 플랫폼**입니다. SYSTEM Oracle DB에 회원·세션·연결 설정·카탈로그를 저장하고, 회원이 등록한 TARGET Oracle DB에서 실제 SQL을 실행합니다.

자동 체험 로그인과 자동 합성 데이터 생성은 제거했습니다. 로그인 후 데이터가 없으면 빈 화면으로 시작합니다. R-BAP과 V-BAP은 C-BAP 없이 기존 TARGET 테이블을 조회하거나 파일을 직접 등록해 사용할 수 있습니다.

## 실행 순서

1. 프로젝트 내부 `venv/`와 의존성을 준비하고 `.env`에 SYSTEM Oracle 연결 정보를 설정합니다.
2. 원격 DB의 초기 오브젝트는 **[database/DDL/install_oracle.sql](database/DDL/install_oracle.sql)** 하나를 SQL Developer의 스크립트 실행(F5) 또는 SQLcl로 실행합니다. 권한·quota와 반복 실행 조건은 [DB 설치 안내](database/README.md)를 확인하세요.
3. SYSTEM 스키마 준비 후 서비스를 시작하고 **http://127.0.0.1:9000**에서 로그인 또는 회원가입합니다.
4. **DB 연결 설정**에서 본인 TARGET DB를 등록·연결 시험한 뒤 SQL 조회, 수집, 분석, 시각화를 진행합니다.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
. 'D:\work\in-baps\.local\ops\enter-terminal.ps1'
baps-start
```

새 VS Code 터미널은 프로젝트의 `IN-BAPS PowerShell` 프로필을 통해 가상환경을 생성(없을 때만)·활성화하고 단축 명령을 등록합니다. 일반 PowerShell은 `.local/open-terminal.cmd`로 열 수 있습니다. 스크립트는 자신의 위치에서 프로젝트 루트를 계산하며 사용자 전역 프로필을 변경하지 않습니다.

처음 옮긴 PC에서는 `.local/ops/setup.ps1`을 실행합니다. Python 3.12 이상을 사용하고, 구버전 기본 Python이 있으면 `-PythonPath 'Python312\python.exe의 전체 경로'`를 지정합니다. 설치파일·잠금 목록·오프라인 설치 절차는 [환경 재현 안내](reference/environment/README.md)에 있습니다.

## 브라우저·바탕화면 아이콘

브라우저 탭에는 IN-BAPS 파비콘을, 브라우저에서 앱/바로가기를 만들 때는 192/512px 앱 아이콘을 제공합니다. Apple 홈 화면 아이콘과 Windows 다중 해상도 ICO도 포함합니다. 원본은 `frontend/assets/favicon.svg`이며 `npm.cmd run icons`로 아이콘 파일을 다시 생성할 수 있습니다.

프로젝트 터미널에서 `baps-shortcut`을 실행하면 `.local/shortcuts/IN-BAPS.url`을 생성합니다. 이 파일을 바탕화면에 복사해 사용하거나 `baps-shortcut -Desktop`으로 바탕화면에 직접 생성할 수 있습니다. Render 주소를 사용하려면 `baps-shortcut -Url 'https://서비스주소/'`로 생성합니다. 프로젝트를 다른 위치로 옮기면 로컬 아이콘 경로가 맞도록 다시 생성하세요. PS1과 URL 바로가기 파일은 Git 제외 `.local/` 안에서 관리합니다.

## 화면 가독성과 팝업

상단 바와 공통 제목의 여백을 줄여 실제 작업 영역을 우선합니다. C-BAP은 반복 안내 배너를 한 줄 안내와 간결한 파일·JSON 카드로 정리했으며 연결된 데이터셋을 바로 아래에 표시합니다. DB 연결 설정의 SYSTEM/TARGET 설명은 펼쳐 보는 안내로 제공하고, SQL 작업실은 편집기 높이와 글자 크기를 유지하면서 도구 모음·패널 사이의 여백을 줄였습니다. 작은 화면에서는 제목·실행 버튼·정식 명칭이 자연스럽게 줄바꿈됩니다.

실제 해상도별 공간 개선 수치와 검증 범위는 [작업 공간·모듈 명칭 검증](reference/VALIDATION_COMPACT_LAYOUT.md)에 기록했습니다.

V-BAP은 데스크톱에서 **차트 유형 → 상세 설정 → 그래프**의 3열로 구성합니다. 데이터셋·축·두 번째 범주·집계 방식과 차트 적용 버튼을 가운데 패널에 모아 그래프를 보면서 조정할 수 있습니다. 화면에 남은 폭에 따라 차트 유형을 위쪽으로 재배치하고, 모바일에서는 유형·설정·그래프 순서로 표시합니다. [상세 설정 배치 검증](reference/VALIDATION_VISUAL_SETTINGS.md)에 해상도별 확인 결과를 기록했습니다.

왼쪽 메뉴는 WORKSPACE·DATA PLATFORM·MANAGEMENT 세 그룹으로 정리했습니다. 상하단 안내 영역을 줄여 1280×720 이상 일반 데스크톱 화면에서는 관리자 메뉴 전체가 스크롤 없이 보이고, 로그아웃은 하단에 고정됩니다. 상단의 메뉴 버튼으로 아이콘 형태로 접거나 펼칠 수 있으며 선택은 같은 브라우저에 저장됩니다. 모바일에서는 메뉴 선택·닫기 버튼·바깥 영역 클릭·Escape로 닫을 수 있습니다. 높이가 매우 낮은 화면에서만 로고와 메뉴 영역을 함께 스크롤하며, 현재 메뉴로 자동 이동합니다.

본문은 16px 기준으로 큰 화면에서 최대 18px까지 조정되며, 입력값·표·메뉴와 보조 설명의 대비를 높였습니다. 입력 예시는 `예:`와 기울임꼴·점선 테두리로 표시하고, 실제 입력값은 진한 글자와 실선 테두리로 구분합니다. 테이블 생성 창은 최대 860px이며 작은 화면에서는 컬럼 입력을 세로로 배치합니다.

알림·오류·필수 입력 안내는 공통 레이어 팝업을 사용합니다. 제목을 드래그하거나 제목에 초점을 둔 상태에서 방향키로 이동할 수 있으며, 창 크기를 줄여도 화면 안에 유지됩니다. 오류는 확인·닫기 전까지 남고 일반 알림은 7초 후 사라집니다. 알림 위에 마우스나 키보드 초점이 있으면 시간이 멈추며, 이동한 알림은 직접 닫을 때까지 유지됩니다. Escape는 가장 최근 알림부터 닫고, 알림이 없을 때 입력 팝업을 닫습니다. 운영체제의 동작 줄이기 설정을 따릅니다.

처리 결과·영향 행 수 같은 작업 기록은 화면에도 유지합니다. 입력 오류 팝업은 작성 중인 내용을 지우지 않으며, 브라우저 기본 검증 말풍선도 공통 레이어로 표시합니다. 구현은 `frontend/js/layers.js`와 공통 CSS에서 관리합니다.

## R-BAP 일괄 분석

R-BAP 분석 설정의 **모든 방법 일괄 분석**에서 그룹 기준·집계 수치/방식·텍스트 컬럼·상관관계 컬럼을 확인하고 **4가지 분석 실행**을 누릅니다. 데이터 프로파일 → 그룹별 집계 → 상관관계 → 텍스트 빈도를 순서대로 실행하며 각 성공 결과는 기존 회원 전용 분석 API를 통해 SYSTEM DB에 저장합니다. 상관관계 컬럼은 2~20개이며, 수치형 컬럼이 더 많으면 처음 20개를 기본 선택합니다.

방법별 결과 카드에서 완료 결과를 골라 상세 결과·CSV 내보내기·V-BAP 연결을 사용합니다. 컬럼 부족은 건너뜀, 실행 오류는 실패로 표시하며 나머지 방법은 계속 실행합니다. 인증·권한 오류 또는 화면 이동 시 후속 방법 실행을 중단합니다. 이미 서버에 전달한 요청을 취소하거나 저장한 결과를 롤백하지 않습니다. 단일 분석과 일괄 분석의 중복 실행은 차단합니다.

하단에 표시된 결과와 일치하는 완료 항목은 코럴 배경·테두리·왼쪽 강조선과 **현재 보기**로 구분합니다. 활성 표시는 왼쪽의 실행 예정 분석 방법이 아니라 실제 표시 중인 결과를 따릅니다.

진행률은 처리한 분석 방법 수 / 전체 4개 기준입니다. 개별 DB 분석 시간의 진행률을 추정하지 않습니다. SQL 데이터셋은 분석마다 원본을 다시 조회하므로 4개 결과가 하나의 DB 스냅샷을 공유하지 않습니다. 결과 카드는 현재 브라우저 세션의 최근 일괄 실행을 보여 주며, 새로고침 후에도 각 분석 기록 자체는 SYSTEM DB에 남습니다. 검증 범위는 [일괄 분석 검증](reference/VALIDATION_BATCH_ANALYSIS.md)에 기록했습니다.

## 공통 작업 진행 표시

로그인 소개와 입력 폼은 넓은 화면에서도 중앙의 약 1080px 영역에 모아 표시합니다. 로그인 성공 즉시 로그인 HTML을 제거하며, 로그인 확인·인법스 초기 준비·메뉴 화면 전환은 **화면 정중앙의 차단 로딩창**을 사용합니다. 전체 배경 흐림과 모달 차단으로 클릭·키보드 접근을 막고 Tab 초점을 유지합니다. Escape로 닫히지 않으며 완료·실패 시 자동 해제됩니다. 초기 데이터 조회 실패 시 재시도 화면을 제공합니다.

DB 연결 테스트·SQL 조회/DML·수집·분석·저장·오브젝트 생성 등 업무 API 작업에는 기존처럼 오른쪽 위의 이동 가능한 진행 창을 표시합니다. 작업명·경과 시간·진행 막대를 제공하며 동시 작업은 각각 표시하고, 완료·실패한 작업은 자동으로 정리합니다. 일반 요청은 0.3초 이상 걸릴 때 표시해 빠른 조회의 깜빡임을 줄입니다. IN-SIGHT 차트 생성도 이 방식을 사용합니다. 중앙 화면 로딩 중에는 오른쪽 진행 창을 숨겨 표시가 중복되지 않게 합니다.

- 파일 업로드: 브라우저가 알려 주는 실제 전송 바이트로 **파일 전송률 %**를 표시합니다. 전송이 끝나면 **서버 검증·DB 저장 중**으로 전환합니다. 전송 100%가 DB 저장 완료를 의미하지 않습니다.
- CSV 내보내기: 실제 변환한 행 수 / 전체 행 수로 %를 표시합니다.
- SQL·분석·DB 저장: 현재 서버 API는 중간 완료 건수를 제공하지 않으므로 움직이는 막대와 경과 시간만 표시합니다. 예상 진행률을 임의로 만들지 않습니다.

성공·오류·입력 안내는 오른쪽 아래의 공통 알림 레이어를 사용해 상단 실행 버튼을 가리는 일을 줄입니다. 입력 팝업 안에서 실행한 작업의 진행·알림도 팝업 위에서 확인하고 드래그 또는 방향키로 이동할 수 있습니다. 오류는 직접 닫기 전까지 유지합니다. 진행 창에는 DB 작업을 취소한다고 오해할 수 있는 닫기·취소 버튼을 제공하지 않습니다.

공통 구현은 `frontend/js/progress.js`, `core.js`, `layers.js`입니다. `api()`는 기본적으로 진행·오류를 표시하며, 백그라운드 세션 확인 같은 내부 요청만 표시를 생략합니다. 신규 API에도 기본 동작이 적용됩니다.

화면 진입 차단은 `frontend/js/page-loading.js`에서 별도로 관리하며 중첩된 준비 작업이 끝난 뒤 해제합니다. [로그인 배치·화면 로딩 검증](reference/VALIDATION_LOGIN_LOADING.md)에 검증 범위를 기록했습니다.

일반 로그인·페이지 이동의 중앙 로딩창은 작은 네이비 패널에 로고·상태 문구·얇은 흐름 막대만 표시합니다. 데이터 노드·분석 파형·회전 궤도가 있는 디자인은 `startPageLoading(label, {variant:'analysis'})`로 명시적으로 선택할 수 있는 별도 스타일로 보관합니다. 현재 일반 업무는 기존 오른쪽 진행 표시를 유지합니다. 두 스타일 모두 외부 이미지 요청 없이 동작하며 운영체제의 동작 줄이기 설정을 따릅니다. 장식 모션을 AI 분석의 실행 여부나 완료율로 표현하지 않습니다.

동시 요청·실패 정리·파일 전송과 DB 처리 단계·CSV 행 기준 진행률·모바일 이동 및 실제 Oracle 연결 확인 범위는 [공통 진행 표시 검증 기록](reference/VALIDATION_PROGRESS.md)을 참고하세요.

## 회원과 데이터

로그인 후 초기 조회는 SYSTEM Oracle 연결 풀을 재사용하고 데이터 목록·저장 시각화 목록을 병렬로 요청합니다. 선택 데이터의 실제 행은 진입 화면에서 한 번 조회합니다. DB 설정·카탈로그처럼 행 데이터가 필요 없는 화면으로 바로 진입하면 TARGET SQL을 실행하지 않습니다. 이후 데이터 화면으로 이동하면 TARGET을 다시 조회합니다.

카탈로그 목록은 SQL에서 `rows`를 제외한 메타데이터만 반환하며, SYSTEM JSON/CLOB은 결과 배치와 함께 읽습니다. 읽기 조회의 불필요한 COMMIT 왕복도 제거했습니다. 세션·소유권 검사는 요청마다 계속 수행합니다. `BAPS_SYSTEM_POOL_MAX`는 프로세스당 SYSTEM 연결 상한이며 기본 4, 허용 범위는 1~16입니다. 설정·접속 정보 변경 후에는 서비스를 재시작합니다. 회원별 TARGET 작업은 별도 연결을 사용합니다.

2026-10-29 실제 Oracle에서 데이터 목록 조회 중앙값은 약 223ms에서 31ms로 줄었습니다. 별도로 로컬 9000 서비스의 로그인 제출부터 메인 표시까지 각 3회 측정한 중앙값은 백엔드 교체 전 약 2.39초에서 교체 후 0.86초로 줄었습니다. 이 브라우저 비교는 양쪽 모두 중복 조회를 제거한 같은 프론트를 사용했습니다. 재측정 방법과 검증 범위는 [초기 로딩 튜닝 기록](reference/VALIDATION_STARTUP_PERFORMANCE.md)에 있습니다.

- 가입한 회원의 기본 권한은 `analyst`입니다. 관리자 계정은 `BAPS_ADMIN_USER`와 12~256자의 `BAPS_ADMIN_PASSWORD`를 설정해 최초 생성합니다. 비밀번호 길이 조건은 신규 생성에 적용하며, 이미 생성된 관리자의 로그인 정보는 DB에 저장된 값을 사용합니다. 기존 일반 회원을 환경변수로 관리자로 승격하지 않습니다.
- 초기 관리자 안내 파일을 생성한 경우 `secrets/initial-admin.txt`에서 로컬로 확인합니다. 비밀 파일은 Git·정적 웹·소스 백업에 포함하지 않습니다.
- 실제 관리자 아이디·비밀번호는 로컬 `.env` 또는 배포 환경의 비공개 변수로 관리합니다. 관리자 로그인 정보 변경 SQL·실행 기록은 Git 제외 경로에 두며, Git 배포 시 현재 관리자 비밀번호가 배포 파일이나 스테이징 내용에 포함되면 중단합니다.
- 현재 로컬 초기 관리자에는 `BASE03 · 기본 TARGET` 연결을 등록하고 실제 접속·SQL 조회를 확인했습니다. 관리자 소유의 SYSTEM 공유 연결이며 다른 회원에게 자동 공유되지 않습니다. 데이터셋은 생성하지 않아 관리자 인법스도 빈 상태입니다.
- 유휴 만료는 기본 30분, 최대 세션 수명은 기본 8시간입니다. `BAPS_SESSION_IDLE_MINUTES`, `BAPS_SESSION_MAX_HOURS`로 조정합니다. 세션 상태 조회만으로 유휴 시간이 연장되지 않으며 화면의 명시적 연장 동작은 CSRF 검증을 거칩니다.
- SYSTEM 접속 정보는 서버 환경에서, TARGET 연결은 회원별로 관리합니다. TARGET 비밀번호는 `BAPS_SECRET_KEY`로 암호화하며 브라우저에 반환하지 않습니다. 키는 최소 32자이며 변경하면 저장된 연결 비밀번호를 해독할 수 없으므로 별도 안전 보관이 필요합니다.
- 샘플이 필요하면 DB 설정 화면의 **샘플 데이터 생성**을 직접 실행합니다. 합성 예제임을 표시하고 선택한 TARGET의 실제 테이블에 적재합니다. 이후 화면은 저장된 테이블을 SQL로 조회합니다.

C-BAP 파일 수집은 쓰기가 허용된 TARGET 연결을 선택해야 합니다. 화면의 R/V 직접 파일 입력도 TARGET에 적재하며, R/V 직접 행 등록 API는 SYSTEM DB 보관을 지원합니다. TARGET SQL 데이터셋은 조회 SQL·바인드·연결 식별자를 SYSTEM 카탈로그에 저장하여 사용할 때 다시 조회합니다. 구체적인 데이터 경로는 [실제 DB 구조](reference/architecture/REAL_DATABASE.md)를 참고하세요.

## TARGET 연결 등록·상세보기

DB 연결 설정(M90002)에서 **Easy Connect** (`host:port/service_name`), **TNS 별칭**, **직접 연결 기술자** (`(DESCRIPTION=...)`)를 선택합니다. TNS 목록은 서버 `DB_WALLET_PATH`의 `tnsnames.ora`에서 읽습니다. 클라이언트 SQL Developer의 저장 연결 이름을 DSN으로 입력하는 것이 아닙니다. TNS/Wallet을 사용할 때는 **서버 Oracle 네트워크 프로필 사용**을 선택합니다. 현재 UI는 서버에 설정한 한 개의 네트워크 프로필을 공유하며, 회원별 Wallet 업로드나 JDBC/LDAP 연결은 제공하지 않습니다.

**연결 테스트 → 연결 저장** 순서로 등록할 수 있습니다. 저장 전 테스트는 접속과 사용자 확인 SELECT만 실행하며 연결 레코드를 저장하지 않습니다. 이름·DSN·계정·비밀번호를 바꾸면 다시 테스트하세요. 쓰기 허용 체크는 DB 권한을 부여하지 않으며 수집/DDL/DML의 실제 권한은 해당 DB 계정을 따릅니다.

모든 TARGET 카드의 **상세정보** 버튼에서 등록 화면과 같은 구성으로 사용자·접속 방식·DSN·서버 프로필·DML 허용·등록/변경 시각을 확인합니다. 일반 연결은 상세 창에서 **수정**할 수 있으며, 비밀번호를 비워 두면 저장된 암호를 유지합니다. 서버 DB 공유 연결도 실제 환경설정의 사용자와 DSN을 읽기 전용으로 보여 줍니다. 비밀번호·암호화 값·Wallet 파일/경로는 반환하지 않습니다.

## TARGET 오브젝트 목록 설정

**DB 연결 설정(M90002)의 TARGET 카드 → 목록 설정**, 또는 **DBMS 작업실(M90003) → 목록 설정**에서 연결별 표시 범위를 관리합니다. 설정은 SYSTEM DB의 해당 연결 `CONFIG_JSON.object_filter`에 저장되어 다시 로그인해도 유지됩니다. 이 기능을 위한 추가 테이블·설치 SQL 실행은 필요하지 않습니다.

- 표시 범위: 내 생성·적재 테이블과 관련 인덱스/트리거, 또는 현재 DB 계정 스키마 전체. SYSTEM 공유 계정의 전체 목록은 관리자에게만 제공하며 일반 회원은 소유 범위를 유지합니다.
- IN-BAPS 시스템 오브젝트 숨김: 기본 선택입니다. 이름 전체를 일괄 제외하지 않고 실제 시스템 테이블·제약 인덱스·관련 인덱스/트리거·카탈로그 뷰·세션 정리 프로시저를 판별합니다. 해제해도 시스템 데이터와 DDL 접근은 열리지 않습니다.
- 이름 접두어 제외: 한 줄에 하나씩 최대 50개. `TMP_`, `BAK_`, `INIT$_TB_BAPS_` 등 실제 접두어를 입력합니다. 대소문자는 무시하고 `_`, `%`, `$`는 일반 문자입니다. `INIT$_` 전체를 제외하면 본인의 수집 테이블도 숨겨질 수 있습니다.
- 유형 제외: 테이블·뷰·구체화 뷰·함수·프로시저·패키지·인덱스·트리거·시퀀스. 목록은 같은 9종의 접고 펼치는 폴더로 제공하고 표시 건수를 보여 줍니다. 최대 1,000개 표시 후에는 제한을 안내합니다.

목록 설정과 SQL/DDL 권한은 별개입니다. 시스템 보호 항목과 SYSTEM 공유 계정에서 다른 회원 소유 항목은 **목록만** 표시하며, 이름·유형·상태를 확인할 수 있습니다. SQL·그리드·DDL의 기존 보호 규칙은 그대로 적용합니다. 제외 조건은 목록 표시만 바꾸며 오브젝트를 삭제하거나 DB 권한을 변경하지 않습니다.

2026-10-29 BASE03 확인 당시 물리 오브젝트는 26개였지만 관리자 연결에 등록된 소유 테이블은 0개였습니다. 이전 화면은 이 소유 목록으로 제한되어 비어 있었습니다. 개편 후 관리자 기본 범위는 스키마 전체 목록이며, 지원 유형 24개 중 시스템 관련 18개를 기본 제외하여 6개를 표시합니다. 시스템 숨김을 해제하면 24개를 확인할 수 있습니다. LOB 내부 오브젝트 2개는 이 탐색기의 지원 유형에 포함하지 않습니다. 검증 범위는 [오브젝트 탐색기 검증 기록](reference/VALIDATION_OBJECT_BROWSER.md)에 있습니다.

SQL 작업실은 선택한 계정의 스키마를 대상으로 단일 SELECT/WITH 조회 또는 INSERT/UPDATE/DELETE를 실행합니다. DML 미리보기는 실행 후 롤백하며, 저장 동작에서 커밋합니다. 일반 DML은 1,000행, 그리드 편집은 한 행으로 제한합니다. 그리드 수정·삭제는 기본 키와 조회 당시 원본 값으로 동시 변경을 검사합니다. DDL/PLSQL 임의 실행, DB 링크, 다른 스키마 참조는 SQL 작업실에서 지원하지 않습니다. 구조 변경은 별도 오브젝트 생성·컬럼 추가 API와 파일 기록으로 관리합니다.

IN-SIGHT는 로컬 Apache ECharts 자산으로 추세·막대·영역·도넛·산점도·히트맵·레이더·트리맵·선버스트·생키·관계 네트워크·박스 플롯·퍼널·게이지 14종을 제공합니다. 선정 근거는 [시각화 라이브러리 조사](reference/VISUALIZATION_LIBRARIES.md)에 있습니다.

파일 입력은 10MiB·20,000행·100컬럼, TARGET 적재 문자열 셀은 UTF-8 4,000바이트 이내입니다. SQL 결과도 행·용량·시간 제한을 적용하며 잘린 결과를 표시합니다. 분석은 조회한 범위에 대해 서버 메모리에서 수행합니다. 토큰 빈도를 형태소·감성 분석으로 표시하지 않습니다. 외부 Open API/SNS/웹 자동수집·스케줄러, 외부 R 실행기, 외부 BI 연계는 아직 구현 범위에 포함되지 않습니다.

## DB 명명·파일 관리

IN-BAPS 시스템 오브젝트는 `INIT$_<유형>_BAPS_<이름>`으로 구분합니다. 테이블 `INIT$_TB_BAPS_*`, 프로시저 `INIT$_SP_BAPS_*`, 뷰 `INIT$_VW_BAPS_*`, 인덱스 `INIT$_IX_BAPS_*`, 제약 `INIT$_PK/UK/FK/CK_BAPS_*` 규칙을 사용합니다. 기존 IN-EDITAONE 오브젝트와 데이터를 이름 변경·삭제하지 않습니다.

**M90003 DB 작업실의 사용자 테이블에는 시스템 명명 규칙을 적용하지 않습니다.** `SALES`, `TB_CUSTOMER`, `sales_detail`, `매출 내역`처럼 접두어와 대문자 형식을 강제하지 않고 이름을 그대로 생성합니다. 소문자·공백 등이 포함된 이름은 SQL에서 큰따옴표로 감싸며, 오브젝트 선택 시 조회 SQL은 자동으로 인용됩니다. 컬럼도 같은 원칙을 따르고 기본 키 제약 이름은 DB가 자동 부여합니다. DB 식별자 길이 검증(UTF-8 128바이트), 권한 검사, SYSTEM 보호와 실행 DDL 파일 기록은 유지합니다.

| 폴더 | 역할 |
|---|---|
| `database/DDL/` | 초기·신규 오브젝트, 반복 설치 SQL, TARGET 생성 템플릿 |
| `database/ALT/` | 기존 오브젝트 변경, TARGET 컬럼 추가 템플릿 |
| `database/DML/` | 기준 데이터·보정 버전 |
| `database/SQL/` | 기능별 앱 SQL ID·바인드 |
| `database/OPS/` | 수동 진단·검증 |

SYSTEM 초기 설치는 기존 데이터 보존과 정의 검사를 수행하며 반복 실행할 수 있습니다. 앱 시작 시 Oracle DDL을 실행하지 않습니다. 이후 변경은 새 버전으로 추가하고 적용된 파일의 체크섬을 바꾸지 않습니다. 이전 `INBAPS_*` 실험판 원본은 `reference/database/legacy-prototype/`에 보존했으며 실행 대상이 아닙니다.

## PowerShell 운영·배포

운영 PS1은 Git 제외 `.local/ops/`, 터미널 설정은 Git 제외 `.vscode/`에 있습니다. Git clone만으로 이 로컬 파일이 복원되지는 않으므로 소스 백업 또는 프로젝트 복사본으로 함께 이동합니다.

```powershell
baps-start                         # http://127.0.0.1:9000
baps-stop
baps-restart
baps-status
baps-backup                        # 소스 ZIP, 비밀정보·원격 DB 제외
baps-deploy                        # 변경 검토
baps-deploy -Publish                # 검사·커밋·push, 한국시간 날짜·시간 메시지 자동 생성
baps-db-plan                       # 연결 없는 버전 계획
baps-db-status                     # Oracle 적용 이력
baps-db-install -Schema 대상스키마 # 반복 초기 설치
baps-db-apply -Schema 대상스키마   # 이후 버전 적용
baps-db-export                     # 실제 SYSTEM 오브젝트 DDL 내보내기
baps-help
```

`baps-backup -IncludeData`는 테스트용 SQLite 스냅샷 옵션이며 **Oracle 데이터 백업이 아닙니다**. Oracle 데이터·암호화 키·wallet은 별도 백업 정책으로 보관합니다. TARGET에서 실행한 생성/변경 DDL은 `.runtime/ddl/`에 남고 SQL 기록만 소스 백업에 포함합니다. 나머지 런타임 상태는 제외합니다.

`baps-deploy -Publish`는 커밋 메시지를 한국시간 기준 `IN-BAPS - yyyy.MM.dd-HHmmss`로 자동 생성합니다. 필요한 경우에만 `-Message '설명'`으로 직접 지정할 수 있습니다.

Git 원격은 [initgroup/in-baps](https://github.com/initgroup/in-baps), 기본 브랜치는 `main`입니다. Render는 별도 IN-BAPS 서비스에 다음 명령을 사용합니다.

- Build: `bash scripts/render-build.sh`
- Start: `uvicorn main:app --host 0.0.0.0 --port $PORT`

운영 환경은 `BAPS_STORAGE=oracle`, `BAPS_ENV=production`, `BAPS_COOKIE_SECURE=true`, 실제 허용 호스트와 공개 HTTPS origin을 설정합니다. SQLite는 격리 테스트용이며 Oracle 실패 시 대체 저장소로 전환하지 않습니다.

## 소스와 검증 기록

배포 소스는 `backend/`, `frontend/`, `database/`, `scripts/` 및 루트 실행 설정입니다. 조사·설계·설치 재현 자료는 `reference/`에 구분합니다. `D:\work\in-editaone`의 메뉴·SQL 외부화·인증·TARGET 분리·DBMS 패턴을 참고했으며 실행 시 원본 폴더에 의존하지 않습니다.

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -p '*_test.py' -v
.\venv\Scripts\python.exe -m compileall -q main.py backend
.\venv\Scripts\python.exe -m backend.migrate plan
npm.cmd run check
npm.cmd run test:charts
npm.cmd run test:ui
```

사이드바 개편 후 브라우저 검사 13개를 통과했습니다. 관리자 메뉴 전체 표시(1920×1080·1366×768·1280×720), 접기 상태 복원, 모바일 메뉴·키보드 초점과 작은 높이에서의 접근성을 확인했습니다. 실제 9000 서비스에서도 기존 관리자 계정으로 메뉴 배치를 확인했습니다. 상세 범위는 [사이드바 검증 기록](reference/VALIDATION_SIDEBAR.md)에 있습니다.

2026-10-29 회원 개편 검증에서 Python 검사 44개, 브라우저 검사 9개, 차트 검사 4개를 통과했습니다. 이 자동 회귀에는 격리 SQLite와 가짜 드라이버를 사용한 API·보안·제어 흐름 및 Oracle JSON 반환 형식 검증이 포함됩니다.

별도로 실제 Oracle에서 SYSTEM 기본 오브젝트 16개의 유효 상태와 읽기 조회를 확인하고, 초기 설치 SQL을 반복 실행했습니다. 데이터 적재 후에도 두 번 재실행하여 SYSTEM 5개 테이블의 기존 행 보존을 확인했습니다. 회원가입·로그인·암호화한 TARGET 연결·C-BAP 실제 적재·SQL DML·그리드·R-BAP 분석·V-BAP 저장·세션 만료까지 10단계 통합 검사를 통과했습니다. 초기 `ORA-01950`은 사용자가 승인한 ADMIN 연결로 해당 SYSTEM 소유 계정의 DATA quota를 100MiB로 설정하여 해결했습니다. 검증용 데이터는 별도 QA 회원에 속하며 새 회원에게 자동 생성되지 않습니다.

Oracle 연결 서비스는 **http://127.0.0.1:9000**에서 시작했습니다. 실제 API를 사용하는 브라우저에서도 관리자 로그인·빈 인법스·기본 TARGET 접속·바인드 SQL 조회·SYSTEM 오브젝트 화면·로그아웃을 확인했고 브라우저 오류는 없었습니다. Git push·Render 공개 배포는 수행하지 않았습니다.
